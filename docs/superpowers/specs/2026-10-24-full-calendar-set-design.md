# Serve the full exchange calendar set (v4 and up)

Status: draft for review, 2026-10-24. Home: BDOBB v4.0.0 and openbq-docker
v4.0.0. Carried to v5 through v10 with an integration review per line, as
the 2026-10-23 calendar work was. Builds on
`2026-10-23-calendar-qualified-expressions-design.md`.

## Intent

Every calendar exchange_calendars 4.13.2 defines can be used anywhere a
calendar is chosen. That means 71 calendars, up from 9, in all of these
places:

- a date expression's `(MIC)`;
- a card's symbol suffix;
- the parameter and widget exchange;
- the dashboard Exchange menu.

User rulings, 2026-10-24:

- Serve the full set.
- Overnight calendars follow the library's convention.
- The dashboard menu lists every served calendar.
- New calendars are qualified by a snapshot plus spot checks.

## One catalogue, generated by the provider

openbq-docker generates `calendar-catalogue.json` from exchange_calendars and
checks it in. It has one entry per calendar, with these fields:

- `calendarId` (`exchange:XPAR`) and the MIC;
- display name and IANA time zone;
- regular open and close, and the break if there is one;
- `overnight`: true when a session crosses local midnight;
- `bounds`: the first and last session date served;
- the library's aliases (for example `NYSE` → `XNYS`);
- `suffixes`: the EODHD and Yahoo symbol suffixes for the calendar.

The provider's `CALENDARS`, its capabilities and its bounds all read this one
file.

BDOBB vendors the catalogue with the existing contract vendoring
(`scripts/vendor-calendar-contract.mjs`), pinned by the pairing. It is never
fetched at runtime. The client builds the following from it, replacing the
hard-coded tables:

- the known-calendar set;
- `EXCHANGE_HOURS` (hours and zones for the weekday fallback);
- the symbol suffix map;
- the window clamp;
- the Help calendar list;
- the dashboard menu.

## Bounds

Each calendar's bounds are the range the library actually covers when asked
for 1990-01-01 to 2040-12-31. Today that is:

- XTKS from 1997-01-01;
- XTAI from 2019-01-01;
- AIXK (Astana) from 2017;
- XSAU (Saudi) from 2021;
- every other calendar from 1990;
- all of them to 2040-12-31.

A future library upgrade that changes coverage changes the catalogue. That
shows up as a reviewable diff.

## Symbol suffixes

The rule is unchanged: last dot-suffix, case-insensitive. The table is
curated per calendar from EODHD's exchange codes and Yahoo's suffixes, for
example:

- XPAR `.PA`
- XAMS `.AS`
- XSWX `.SW`
- XKRX `.KS` and `.KQ` (Yahoo), `.KO` and `.KQ` (EODHD), covering KOSPI and KOSDAQ
- XSHG `.SS` and `.SHG`
- XBOM `.BO`
- XSES `.SI`
- BVMF `.SA`
- XMEX `.MX`
- XJSE `.JO`

A suffix that maps to more than one calendar infers nothing and falls
through, like an unsuffixed symbol. The table records every ambiguity it
drops. So do symbols that name no exchange calendar: crypto, FX, and futures
roots without a suffix.

## Overnight calendars

The overnight calendars are `24/5`, `24/7`, `CMES`, `IEPA` and
`us_futures`. A session is labelled by the date it closes on, as in
exchange_calendars:

- `T@open(CMES)` on Monday is Sunday 17:00 America/Chicago.
- `T@close(CMES)` is Monday 17:00 (the library models CME as 17:00 to 17:00, with no daily maintenance break).
- `bd` counts sessions.
- `trade_date` is the last session whose close is at or before now.
- `24/7` has a session every day.

These five resolve only from provider bundles, on every card, bound or
legacy. The weekday table cannot describe a session that crosses midnight.
If the bundle is not loaded, the card shows a visible error; it is never
resolved on weekdays.

## Dashboard Exchange menu

The six fixed MICs are replaced by a searchable list of every catalogue
calendar. The list shows the name and MIC, with "Default (XNYS)" first.
`parseExchange` accepts any catalogue calendar. Stored dashboards that use
one of the six still load unchanged. A stored value outside the catalogue
stays visible for repair, as the 10-22 design asks.

## Qualification

Every calendar gets a generated conformance fixture: a snapshot of its 2026
sessions with the catalogue digest, evidence `library_baseline`. This pins
the library output against drift.

The major exchanges also get two or three hand-checked holidays or session
times each, verified against the exchange's published calendar:

- XPAR, XETR, XSWX, XSHG, XKRX, XBOM, XSES, BVMF, XMEX, XJSE, XASX;
- CMES, including a Sunday-evening open.

The evidence-strictness ruling is unchanged.

## Out of scope

- Joint and FX calendar sets in expression syntax.
- Settlement or bank calendars.
- A calendar exchange_calendars does not define.

## Tests

- Provider:
  - each catalogue calendar builds a bundle inside its bounds and refuses
    outside them;
  - each snapshot fixture matches;
  - the catalogue regenerates byte-identical;
  - the hand checks pass.
- Client:
  - every suffix maps to its calendar, and the ambiguous ones infer nothing;
  - `(XPAR)`, `(XKRX)` and `(CMES)` resolve;
  - `T@open(CMES)` on Monday gives Sunday's open;
  - a legacy card on CMES loads the bundle or shows a visible error;
  - the menu lists every calendar and is searchable;
  - stored six-MIC dashboards load;
  - the Help list matches the catalogue.
- Walk: each of v5–v10 passes its gates and an integration review.
