# Rulings I made

These are the chronological execution rulings from the project ledger. Each includes the practical cost if the choice proves unsuitable.

1. **Use managed isolated worktrees rather than donor branches.** Cost if wrong: Extra port reconciliation if the bases differ.

2. **Turn plan assertion sketches into real behavioral tests.** Cost if wrong: Some fixtures need adaptation.

3. **Refuse paged histories and require evidenced complete or bounded snapshots.** Cost if wrong: Live paged sources cannot use these history recipes.

4. **Run recipes in a dedicated local worker after the existing executor.** Cost if wrong: An additional structured clone and worker lifecycle.

5. **Honor the inclusive 10% estimate threshold despite inherited floating-point error.** Cost if wrong: A small intentional difference from donor code.

6. **Replace private local paths in committed documentation with repository references.** Cost if wrong: Less convenient machine-specific navigation.

7. **Keep original statement line identity and expense sign when moving presentation sections.** Cost if wrong: Moving a line does not redefine its financial role.

8. **Preserve donor reset semantics: section reset is section-level; line reset restores home; reset all clears placements.** Cost if wrong: Section reset alone does not undo every line move.

9. **Adapt v9 statement presentation metadata for durable moved-line preview and export.** Cost if wrong: Another existing metadata path must remain consistent.

10. **Refuse new recipes in the synchronous legacy figure path.** Cost if wrong: Invalid execution paths show a repair/refusal instead of a fallback chart.

11. **Normalize omitted legacy measures to an empty array for validated recipe imports.** Cost if wrong: Input normalization differs from the canonical saved shape.

12. **Carry actual acquisition evidence and omitted date/symbol coordinates, never hidden prices; refuse when evidence is absent.** Cost if wrong: Some projected or filtered sources remain unavailable.

13. **Use the union of delivered yield tenors, preserving observed gaps without inventing unobserved tenors. Requested and observed dates remain separate after review.** Cost if wrong: Unseen tenor slots have no plotted observations.

14. **Keep historical heatmaps within acquired years and note an out-of-window incomplete current month.** Cost if wrong: An additional status note instead of empty years.

15. **Refuse absent selected correlation symbols and use actual delivered dates for the shared cutoff, retaining synthetic gaps only as barriers.** Cost if wrong: A partially missing selection cannot silently shrink the matrix.

16. **Require presented or payload-proven instrument identity for projected estimate ranges.** Cost if wrong: Identity-poor projections must be repaired or refused.

17. **Restore the shipped provider v9.0.1 baseline before repackaging.** Cost if wrong: An additional seven-file preservation port and review.

18. **Use the existing static fixture backend and shared explicit snapshot decoder for the importable example.** Cost if wrong: The companion example server must be running.

19. **Keep withheld quarters visible on the axis; preserve frozen web-preview pins because the new route is already admitted, documenting candidate pairing separately.** Cost if wrong: Explicit axis bounds and separate preview/candidate metadata.

20. **Replace the inert canonical test placeholder with an accepted SDK/public-check spelling and repin/reverify the package.** Cost if wrong: A test-only commit and image revalidation.

21. **Leave live account coverage and the 10% heuristic calibration outside recorded-fixture validation.** Cost if wrong: Live entitlements and calibration remain unverified.

22. **Do not add automatic acquisition from paged sources.** Cost if wrong: A complete acquisition must be supplied separately.

23. **Keep exchange calendars, forward estimate revisions and portfolio optimization deferred.** Cost if wrong: Those analyses remain unavailable in this scope.

24. **Keep deployment, other release lines and non-Chromium verification outside this local handoff.** Cost if wrong: Additional release/platform checks remain necessary for those uses.

25. **Require positive instrument identity for cross-row bullet comparisons; retain single-row legacy numeric displays.** Cost if wrong: Identity-poor multi-row bullets require source repair or filtering before comparison.

26. **Defer the duplicate error notice on a failed bullet/waterfall relink.** Cost if wrong: users receive a repeated visible or assertive notice; the old chart still clears correctly.
