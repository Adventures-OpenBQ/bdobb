## Important

1. **The generated screener table labels a 5% return as 0.05%.** Canonical `openbq_eodhd/models/screener.py:82` specifies `formatterFn: "percent"`. BDOBB `src/lib/widgetsJson.ts:309` preserves it and `src/lib/format.ts:120` appends a percent sign to the stored number. Reproducer: upstream `refund_5d_p=5` produces `price_change_5d=.05`. Calling the actual BDOBB formatter on .05 returned `0.05 %` with the emitted formatter and `5 %` with `normalizedPercent`. The Plotly chart already shows 5%. Both canonical `tests/test_eodhd_router.py:142` and Docker `v9/eodhd/tests/test_stack.py:107` assert the incorrect string. Use the fractional-percent formatter in the generated widget, update the paired pin and verify the *displayed value* from that generated field. Correct the provider and validation claims as needed.

2. **Explicitly paged dividend acquisitions can claim complete event coverage.** BDOBB `src/lib/tableRowValues.ts:44` separately accepts the file's acquisition scope and its typed receipt. `src/lib/widgetData/chartRecipes/dividendSteps.ts:64` uses the receipt alone. Reproducer: load the existing one-row verified dividend fixture as a local JSON file, changing only its outer `completeness` from `bounded` to `paged`. The actual file loader and worker returned success, one marker and “Verified acquired window 2026-01-01 to 2026-06-30 inclusive.” The same branch accepts an explicitly partial or sampled source. A page cannot certify a continuous event history. Reconcile explicit negative delivery scope where the acquisition is parsed, including a backend results envelope that explicitly declares paging. Preserve support for an ordinary matched HTTP result array that has a verified typed receipt and no explicit negative delivery claim. This finding does not require a generic completeness gate in the renderer.

3. **Acquisition checks accept contradictions before projection can hide them.** BDOBB `src/lib/widgetData/chartRecipes/financialEvidence.ts:194`, `:211`, `:288`, `:310` and `:324`. Concrete independent probes against the existing fixture shapes produced these results:

   - A screen with `ALPHA.US` and `BETA.TO`, both declaring `exchange=US` and `currency_symbol=$`, passed `parseFinancialEvidence` and `financialRowsAgree` with a wholly safe USD cohort. Filter out `BETA.TO` and the worker's presented-row exchange check never sees the incompatible identity. Validate the qualified suffix against the delivered exchange at acquisition.
   - Adding `amount_basis: "unadjusted"` to the delivered verified dividend row still produced a successful “Split-adjusted to current-share terms” chart in the actual worker. A receipt with `diagnostics:["instrument_conflict"]` and `unsafe.instrument_conflict=false` also produced that chart. Honor an explicitly supplied basis and reject internally contradictory indications of a raw conflict. An unsafe but internally consistent receipt can still be retained for repair diagnostics.
   - An income row declaring `fiscal_year=2026, fiscal_period="FY"` and a matching-date receipt declaring `period_kind="FY", fiscal_year=1981, fiscal_period="Q2"` passed the actual file loader and retained the erroneous period proof. The Sankey resolver consumes those receipt labels at `src/lib/widgetData/chartRecipes/incomeSankeyInput.ts:58`. Check kind/label compatibility and any canonical fiscal facts the delivered row supplies. Preserve genuinely unknown fiscal labels and the documented freedom to rename a *display* column.

   Enforce these at the acquisition boundary shared by local files and matched HTTP receipts and retain unsafe facts across subsequent filtering. Cover the corresponding accepted/unsafe forms through a projected or second-linked chart. This issue is separate from honest source authorities supplying incomplete coverage.

4. **Month-only fiscal inference mislabels week-based fiscal years and quarters.** Canonical `openbq_eodhd/models/fundamental.py:142` and `:153` use the period end's calendar month relative to a nominal fiscal year-end month. A 52/53-week issuer whose year ends on the Saturday nearest January 31 can close FY 2025 and its fourth quarter on Saturday, February 1, 2025. Calling the actual chart helper with that date and fiscal year-end month 1 returned `(2026, "FY")` for annual and `(2026, "Q1")` for quarter. These labels enter the positive snapshot path as acquired facts and appear in the Sankey title and choices. For chart evidence, preserve the actual end and FY/FQ kind, and use a proven fiscal label or leave it unknown when the month-only rule cannot determine it. Keep legacy statement compatibility. Add a fiscal-boundary fixture exercising the snapshot receipt through the displayed label.

5. **A draft can replace a working chart with a refusal already determined by its receipt.** BDOBB `src/components/renderers/LinkedChartRenderer.tsx:107` and `:117`, `src/components/renderers/LinkedChartRecipeControls.tsx:118`. Reproducer: open a working ordinary chart over the paired dividend source, choose Dividend steps and use its normal nonempty response. The live route supplies a qualified instrument and unknown coverage. The loader offers that instrument, every required binding resolves, and Apply becomes enabled. Applying replaces the working chart with the unconditional unknown-coverage refusal. The same decision omits known screen-cohort conflicts and unknown monetary scale for income. Share the existing static receipt/selected-cohort/selected-period admission checks with draft choices and show the specific repair reason before saving. Maintain worker enforcement for applied settings and refreshes. Add a mounted-parent regression using a *valid but ineligible* receipt, in addition to the existing missing/malformed/wrong-kind cases.

6. **A newly linked verified-empty dividend source cannot be selected in the UI.** BDOBB `src/components/renderers/LinkedChartRecipeControls.tsx:39` and `:74`; the dropdown disables the recipe based on this result in `src/components/renderers/LinkedChartRenderer.tsx:225`. Reproducer: open the canonical verified-empty fixture as a local file, link a new chart and choose its type. The actual loader supplies no columns. The type-availability function returned “Present raw fields for ex-dividend date, split-adjusted amount, payment currency.” The same dataset *does* return the correct verified no-events message when a pre-existing valid recipe is sent to the worker. On first use, recognize the validated empty source and permit its canonical empty bindings, with its acquired instrument. Keep unknown coverage and filtered-to-zero sources distinct. Test starting from a newly created chart, rather than refreshing an already applied one.

7. **Plotly can clip a listing used in the regression even at ordinary percentage magnitudes.** BDOBB `src/lib/widgetData/chartRecipes/bubbleRegression.ts:108` accepts a nonconstant span whenever `10000 / span` is finite. This overlooks cancellation during Plotly's scale-and-offset pixel conversion. Using the real builder and installed Plotly in Chromium, I plotted three equal-cap listings with X values `0.1`, `0.10000000000000002` and `0.10000000000000003`, and Y values 0, .01 and .02. At 780 × 480 the actual X plotting domain was **695 px**. The three marker SVG translations were **0, 512 and 1024 px**, so the third listing was clipped entirely. The card still reported three usable listings and `N=3, R²=1`. Bound relative offset versus span as the dividend builder does, or choose a stable representable axis range. Validate marker positions and the fitted endpoints against the actual SVG domain across chart sizes.
