### Important • I1 • A tab switch submits an un-run issuer change

**Location.** BDOBB src/hooks/useWidgetData.ts:203, :217, :225 and :284; src/components/DashboardGrid.tsx:372 and :380. The existing off-tab draft test starts at src/components/DashboardGrid.backendKpi.test.tsx:214. It keeps its headless runner mounted for the entire scenario.

**Observed.** A two-tab dashboard contains a linked P/E card on A and its Run-button backend table on B. After AAPL completes and the KPI displays 19.875×, open B. Its on-display refresh still asks for AAPL. Edit the stored symbol to TSLA without Run. The source becomes pending/updating, and the edit issues zero GETs. Switch back to A. The replacement off-tab runner issues a real TSLA GET. Completing it displays **33.25×** without a Run. The probe used the existing DashboardGrid HTTP harness and table boundary. Vitest recorded one failing selected assertion and 14 unselected cases. Expected the previously committed symbol AAPL for any mount refresh, received TSLA. An earlier probe setup was corrected to accept both pending and updating before the test reached the tab switch. Private reproduction and output are at /tmp/eight-tab-review.uA2Kkd/src/components/DashboardGrid.backendKpi.test.tsx:285 and /tmp/eight-tab-review.uA2Kkd/tab2.log.

**Cause and impact.** Each producer hook initializes its armed question locally. On a new mount it copies current editable parameters; the armed-requests registry has no restoration path for the successor. Although the source remains required in the same dashboard across the tab change, switching React owners turns an ordinary draft into a source acquisition. The receipt and returned rows agree with the TSLA GET. The error is authorizing that GET and committing that question. This can spend a request and change the financial value shown merely by navigating to the chart.

**Required correction.** Carry the committed question across mounted-card/off-tab-runner ownership transfer for the same dashboard and source. Keep normal first acquisition and appropriate refresh behavior, reject incompatible producer identities, and preserve explicit Run, calendar/fiscal holds, source replacement and disposal. Exercise both handoff directions, a draft revert with no TSLA acquisition, and a deliberate Run that can then admit TSLA. Ensure any saved in-memory arm cannot leak to a different dashboard/card or revive a retired request. The provider and Docker pin are unaffected by this finding.
