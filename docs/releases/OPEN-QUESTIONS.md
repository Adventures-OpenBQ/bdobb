## Resolved

- **Connections export/import (`backendsJson`), raised 2026-10-11 by the Episode 7 handover, gap (d); ruled 2026-10-16 by the user: keep, on v7 and later.** **Export…** and **Import…** in the Connections dialog (`src/lib/backendsJson.ts`; `exportBackends` in `ConnectionsDialog.tsx`, landed in `4ccc297b`) are the in-app way to bring connections onto an iPad. The export writes stored credentials (`headerValue`) in the clear, as `backends.json` on disk does, except a value kept in memory only. The dialog warns: "Exports may include stored credentials in plain text." Import merges by id (update, append, never remove): the file's entry wins, a same-header secret the exporter held in memory only is kept, and a cleared credential is not resurrected. Stripping or encrypting the credentials was considered and not taken.
- **#40 (V6-004), ruled 2026-10-10: option (a).** No tool could set a card's view, yet Rita claimed a "chart" in 2 of 2 live runs. `add_widget` and `set_widget_params` now take `view`: default, chart, statement, calendar, raw or transposed. The value must be one the card's view menu could offer (`possibleViews` in `src/lib/cardViews.ts`); anything else refuses the whole call. Undo restores the previous view. Chart and Calendar draw only when the data has a date or time column, and both tool descriptions say so. Option (b), a description-only change, was not taken.
- **Fiscal period labels (dev v9.0.3), ruled 2026-10-15.** Home line: v5, the home of the Statement view. Landed in `681ea23`. A statement widget's period choices, group chips and Groups menu read FY / FQ / TTM / FQ YoY. Statement rows are relabelled from the v4 `fiscal_year_end` lookup, sharing its cache, before the table, the Statement worker, charts and export read them. An unknown year end shows *Fiscal labels as reported*. Decisions: OpenBQ's Statement model is kept. The relabelling only rewrites the `fiscal_year` / `fiscal_period` columns, and an explicit template `fiscal_binding` already parses `FY2027` / `2026` and `FQ2` / `Q2` (pivot-core `fiscal_number`), so nothing in the model changed. Dev's Rita fetch correction (191610b01) is not carried because v5 has no agent. It belongs on v6 when the line is walked.
- **Dev `state.pivotView` import, ruled 2026-10-15.** Home line: v5. Landed in `80c6da6`. A dev v5.7 `pivotView` imports as the Statement view, and its `collapsed` sections become the card's folds. - **Live-grid websocket auth (dev 98301b6), checked 2026-10-11.** `buildWidgetWsUrl` applies only query-placed auth. A browser WebSocket cannot send a header, so a header-auth backend gets no credential on the handshake. User ruling: fix only if a clean target actually refuses the socket. The clean live grid targets OpenBB's reference backend, whose `/live_grid_ws` accepts every connection without auth, so nothing is refused and this is not changed. Revisit if a header-auth websocket backend becomes a clean target.
