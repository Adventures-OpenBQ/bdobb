# BDOBB v8.0.0 — Adventures in OpenBQ

BDOBB 8.0.0 is one release (ruling R4) carrying the News wire and its web relay, pinned cards, locked widgets that sync, and Rita's `pin_card`, on top of clean v7.0.0 — including everything in the v7 rebuild (`v7.0.0` re-cut `ba935b5`, merged as described below). It pairs with openbq-docker v8.0.0. The assembly ledger is `docs/releases/v8-assembly.md`; per-file dispositions are in `docs/releases/v8-delta-manifest.tsv`; source provenance is in `docs/releases/provenance.md`.

Status: **frozen, cloud half** (2026-10-12), and **re-frozen** after the v7 rebuild merge (2026-10-14; receipts in `docs/releases/validation/v8/v8-refreeze-2026-10-14/`). The Mac half (WebKit e2e, native macOS and iPad builds, the live openbq-docker web profile) is pending. Nothing is tagged, pushed or published.

## What is new

- **Pinned cards.** A card's `⋯` menu has **Pin widget ▸** — **Pin to top**, **Pin to bottom**, **Unpin**. A pinned card leaves the grid for a full-width band at that edge of its tab and stays in view while the rest scrolls; one card per edge per tab (a second swaps the first back), corner grips resize the band, Unpin returns the card where it was. The pin is saved with the dashboard, syncs with it, and travels in a new **v8 profile** of BDOBB's apps.json extension; the plain OpenBB export writes none of it, and Duplicate and Copy to never copy it.
- **News.** A new built-in, **News**: a headline wire from an rss-ticker server, with feed tabs you define and can drag to reorder, highlight keywords, a vertical list or a horizontal strip with auto-scroll, double-click to open a story in the browser, the live/reconnecting dot, and `rss-agg.json` export and import. The card has no title bar; its menu opens from the chevron on its strip. Feeds travel in the v8 extension and the dashboard sync.
- **The News web relay.** The web preview relays the wire through openbq-docker v8's `funnel-gateway` (`web` compose profile) for the operator's approved feeds only: the REST history at `/news/api/news` and the `/news/ws/news` socket, opened on the gateway with a short-lived signed ticket. The preview's routes are `/api`, `/news` and `/state`; there is no `/ai`. The vendored gateway policy now comes from openbq-docker, and `package.json`'s `openbqDocker` key names the openbq-docker commit it pairs with (the older `openbbDocker` key is historical).
- **Locked widgets.** **Settings ▸ Locked Widgets** opens an editor for a band along the top or the bottom of the window on every dashboard, tab and workspace (green **+** or `⌘K` to add, a 2–24 row stepper, **Cancel** undoes everything since it opened, **OK** keeps it). A locked widget is live but offers nothing that would change it outside the editor. The bands are one hidden dashboard, `dashboards/docks.json`.
- **Locked widgets sync and travel.** The bands sync with a Workspace server as one hidden record per account (`/pro/dash/sync/system/docks` on openbq-docker v8), newest edit wins, in key and login modes. **Export locked widgets…** and **Export all dashboards…** carry them in the v8 extension; any import of them goes through one guard (empty bands are filled; populated bands ask **Replace** or **Keep mine**). No shared example carries locked widgets.
- **Rita's `pin_card`.** Rita's eighteenth local tool pins a card on the active dashboard to the top or bottom of its tab, or unpins it, as one Undo step; on a locked widget it changes nothing and says why.
- **The rail's "Add widget (⌘K)" row is gone.** The green **+** at the end of the tab strip (and in the Locked Widgets editor) adds a widget, the **Widget Library** row opens the same library, and `⌘K` still does.
- **An import degrades instead of refusing.** v8 data an older or damaged file carries that this version cannot read is skipped per card and named in the notice; the dashboard still imports. The sync does the same with a v8 record it cannot read and hands it back unchanged.
- **A saved card keeps its Workspace server state.** Saving a dashboard no longer drops a card's `extensions` (the server's own widget record, grid entry and mapped params), so the next sync uploads the server's widget instead of a minimal one under the local id, and a dashboard copy keeps it too. Only plain JSON data is written. The same fix is carried into v4–v7 (re-frozen locally as 618812b, 9cab3b3, 3f3cdb8 and 4a464c9).

## Everything in the v7 rebuild

8.0.0 includes everything in the v7 overnight rebuild (`v7.0.0` = `main` `ba935b5`, which carries the v4.0.0, v5.0.0 and v6.0.0 re-cuts), merged into this line by "Merge of the v7 rebuild (ba935b5)" in the ledger:

- **Workspaces:** a minimum resolution per workspace, uniform zoom when the screen is smaller, **Open at launch** with the largest-fit launch choice, and the Workspaces dialog.
- **Save…:** one **Save…** on a dashboard row, whose Format pop-up (or, in the browser build, a flyout) picks **Strict OpenBB Workspace** or **BDOBB Workspace**. It replaces the two export rows; **BDOBB Workspace** writes the v8 profile whenever a dashboard holds pins or News feeds, and **Export all dashboards…** stays on the section menu for every dashboard and the locked widgets.
- **File ▸ Import apps.json…** in the desktop menu bar, running the same import as the rail (and so the same locked-widgets guard).
- **Connections ▸ Export… / Import…** (`backends.json`), and the rail's export/import notice clearing after ten seconds or when the rail folds.
- **The Rust Pivot foundation** (PR #45): a portable Rust/Wasm Pivot engine behind the TypeScript default, with its build (`pnpm pivot:build`), verification and packaging checks; the web preview's CSP admits Wasm.
- **The backend table's Pivot button**, driving its in-thread pivot (hidden on a locked widget, like every other Pivot), and the pivot's Count of a leaf row.
- **Tables and filters:** prefilled `YYYY-MM-DD` date filter boxes that stay relative and re-resolve on refresh, Clear and the row count on one line, CSV and Excel headed by `headerName`, a Widget Library whose search and filters stay put, a Backend filter in the Apps library, and the OpenBB logo on an OpenBB reference connection.
- **openbq-docker:** apps-sync writes the examples into openbq-docker's `examples/bdobb/apps.json` (the two 8.0.0 examples are mapped too); the key-restart notice names `openbq-api`; the Date expression tab in the V4 core tools example; the Run tooltip names ⌘-click hard refresh again; Help describes the openbq-docker stack, with Rita and MCP, and its page now also carries openbq-docker v8's `web` profile.
- **CI:** WebKit installed for the `*-webkit` specs, and a 6 GB Node heap for the app build.

## Examples

- `docs/examples/v8.0.0-news.apps.json` — *Example Dashboard - Version 8.0.0*: one News card with fourteen feeds under four tabs.
- `docs/examples/v8.0.0-pinned.apps.json` — *Example Dashboard - Version 8.0.0 - Pinned Cards*: a Note pinned to the top and a Clock to the bottom over a long Markdown card; built-ins only.

Every example's description now names the minimum BDOBB it needs. Both v8 files open in BDOBB 8.0.0 or later; an earlier BDOBB refuses them rather than dropping what it cannot read.

## Compatibility

- apps.json: v3–v5 profiles are unchanged and strict; a v8 file imports on 8.0.0 or later only.
- Workspace sync: a v7 install syncs a v8 dashboard normally and does not see its pins or News feeds, which ride a sibling record (`extensions.bdobbV8`).
- openbq-docker: 8.0.0 pairs with openbq-docker v8.0.0 (the commit `package.json` `openbqDocker` names). The `web` profile and the hidden docks route are v8 stack features; against an older stack the docks stay local and the preview has no News.
