# BDOBB v10.0.0 — Adventures in OpenBQ

BDOBB 10.0.0 is Episode 10's release: the **live grid** as a streaming table card, with logos and range bars from the backend's `symbol_meta`, the web preview's half of live-grid's `/grid` relay, and the Episode 10 live-grid example, on top of clean v9.0.0. It pairs with openbq-docker v10.0.0, whose opt-in `live` compose profile runs the live-grid sidecar and its kdb+ cache. The assembly ledger is `docs/releases/v10-assembly.md`; per-file dispositions are in `docs/releases/v10-delta-manifest.tsv`; source provenance is in `docs/releases/provenance.md`.

## What is new

- **The live grid is a table card.** A `live_grid` card fetches its snapshot, then streams over the widget's `wsEndpoint`: each update — one row object, as OpenBB's reference backend and the stack's live-grid send it, or a list of rows — is merged into the row with the same identity column, field by field, and a new symbol is appended. Editing the symbols re-sends the subscription over the open socket, re-fetches the snapshot and drops a removed symbol's row, even when a tick for it was already on its way. Seed rows without the identity column are all shown. It has the table card's saved sort, filters, pins and widths, the filter row, cell clicks and Refresh (which re-fetches the snapshot), and a `sendToAgent` row follows Context sharing and the off-limits rule as a table's does. Its Refresh control turns stale whenever the socket is not open: reconnecting, a first connect still waiting, or the card minimised. A socket drop is logged once per card, with the address's query removed.
- **v3 reference compatibility is kept.** The v3 renderer was extended, not replaced: OpenBB's reference `/live_grid_ws` (no auth, one row per frame, the `{"params":{"symbol":…}}` subscription) works as before, asks for no `symbol_meta` and gains no columns.
- **Logos and range bars.** A grid whose columns read a logo or a 52-week end asks the backend's `symbol_meta` for its symbols and fills them in; a backend without it is not an error.
- **Three new column declarations, on any table:** `logo` (the cell's URL as an image; blank or `NA` draws none), `rangeBar` (a CSS track marking a row value between two row fields, palettes `week52` and `day`; the value defaults to the row's `price`, V10-P2) and `percentKey` (a fraction shown in brackets after the value), plus column `align` and tabular digits in table cells.
- **Web preview `/grid` relay.** `web/server.mjs` relays live-grid's widget documents, snapshot, `symbol_meta`, series, chart, ticks and tick chart under the vendored openbq-docker v10.0.0 policy's grammars, and the ticketed `/grid/live_grid_ws` socket with its repeating frame contract, where each frame after a socket's first costs the user one unit of the per-minute budget and every frame spends one per symbol from the user's daily share of the gateway's vendor quota (`GRID_DAILY_SYMBOLS`, default 2500), and seeds a **Live quotes** tab. The preview shows no logos: its content security policy loads images from its own origin only, and live-grid's logos are on `eodhd.com`. Under a policy without the grid rules (openbq-docker v8.0.0's) every `/grid` route is refused; both are tested.
- **The Live Chart is drawn (V10-P4).** live-grid's `live_chart` card draws candles and volume on the same lightweight-charts module as the TradingView card, with its theme and TradingView credit. It seeds from the widget's `/series` for the first symbol in its param (the card says so when there are several) and then folds each update from the live grid's socket into the newest bar with the chart's incremental update, bucketed by the card's interval. A tick's time comes from its row's `updated_ts`, the full UTC instant, or from `updated_at` on an older live-grid. Bar volume is the rise in the row's `stream_volume`, which counts only what the stream has seen and which a re-seed never resets; without it, the rise in the row's day `volume`, and without either, `last_size`. A socket that reopens re-seeds the bars, so the outage's bars come from `/series`, and its first update adds no volume. An interval the chart cannot read shows the fetched bars with a note and opens no socket, and an update stamped more than a minute ahead is placed at now. The socket path is the live grid's: socket tickets for a header credential, reconnect with backoff, and the `{"params":{"symbol":…}}` frame. Refresh re-fetches the seed, a symbol or interval change seeds again, and the refresh control turns stale while the socket is down. A widget without a `wsEndpoint` shows the seeded chart.
- **Help.** Quick Help's **Tables** gains *Live grids* and the new declarations, and **Troubleshooting** a live grid that never ticks; the Reference Manual's Tables, Troubleshooting, Running and Refreshing, Backends and Connections, Web Preview and Example Dashboards pages are updated.

## Examples

- `docs/examples/v10.0.0-live-grid.apps.json` — *Example Dashboard - Version 10.0.0 - Live Grid*: Live quotes over seven symbols, the subscription list, AAPL's kdb+ tick history, the Live Chart and the Cached Price Chart, all live-grid widgets. The Live Chart draws as a live candlestick chart (V10-P4). It opens in BDOBB 10.0.0 or later, and `scripts/apps-sync.mjs` routes it to live-grid's own `apps.json`.

## Compatibility

- apps.json: no profile changes. The example needs only the v3 envelope.
- Credentials: a header or cookie credential does not reach a live grid's socket (a browser websocket carries no header), and the app does not move it into the URL. With a header credential the app fetches a single-use socket ticket from the backend's `ws_ticket` before every connect, and openbq-docker v10.0.0's gateway issues one (V10-P1, ruled 2026-10-15). A ticket request that has not answered within ten seconds falls back to the plain address and the reconnect backoff. A backend that issues no ticket and checks a header on the handshake refuses the socket, and the grid holds its snapshot. The web preview's socket authenticates by a gateway ticket the web layer signs.
- openbq-docker: the live-grid widgets exist only on a stack running live-grid (openbq-docker v10.0.0's `live` profile). `openbqDocker` names the openbq-docker commit that the v10.0.0 tag points at; the older `openbbDocker` key is historical.
