## Implementation and API handoff

`rust/providerFactory.ts` exports `createTableProvider(widgetId, engine: 'typescript'|'rust', options?: {locale?: string; workerFactory?: ()=>Worker}): LocalWorkerExecutor` and `resolveTableEngine()`. The factory selects the existing TypeScript worker or real `createRustExecutor` Web Worker path, with no fallback after initialization/calculation failure. `VITE_TABLE_ENGINE=typescript|rust` is a developer/test override only when `import.meta.env.DEV` is true. Release builds ignore it and default to TypeScript until Task 12 acceptance. Invalid explicit engine choices/development overrides refuse structurally.

The store's existing `executor` injection remains available. Optional `engine`/`locale` now select the default factory for root, linked subset and repair executors. Its saved-card comparison baseline, definition/selection authority, acquisition generations, source coordinates, durable reconciliation/publication ordering and linked subset ownership stay in the existing store. No persistence/CSS/TableRenderer implementation changed. Engine selection is resolved at executor creation; existing nodes retain their executor. Compiled build environments have a fixed override; tests can select each engine explicitly before creating nodes.

An explicit locale is canonicalized and validated. Unsupported locales/extensions, silently dropped collation extensions, or requested resolved locales differing from ambient worker locale refuse with `UNSUPPORTED_CAPABILITY` before acquisition. Malformed locale values yield `INVALID_REQUEST`. Matching ambient locale is supported through both direct factories and Task 9 `createLocalExecutionProvider(options => createTableProvider(options.widgetId, engine, {locale: options.locale}))`. Configurable cross-locale worker transport remains deferred; the factory does not ignore locale.

The application factory deliberately returns the acquisition-capable local facade required by the plan. It does not make remote sessions register local datasets. Task 9 snapshot-bound `ExecutionProvider`/`ProviderSession` remains the common provider contract; factory-backed common local sessions and `tableExecutorAdapter` are tested with negotiated safe-exact admission. The store's local numeric count interface already receives validated complete-session exact counts through worker protocol validation. No generic estimated/unknown count is converted into an exact count and no production remote provider was added.

Rust factory apply/preview run the existing Task 9 declaration/structural capability preflight before native dispatch. Unknown/malformed serialized formula ASTs therefore yield structured `INVALID_REQUEST` before native publication rather than trapping deserialization. The approved spec/plan appendix records the compatibility exception: TypeScript formerly tolerated some corrupt ASTs with partial independent cells; Rust refuses that whole candidate recoverably, preserves authored intent and the prior publication for unchanged input, and allows repair without acquisition. Supported known ASTs with missing references/cycles/type errors retain independent linked values and diagnostic cells. The narrow native validation fix retains known-node/ID shape, versions, prototype, depth/node/text/selector/budget guards but delegates formula/measure reference existence to the existing compiler/evaluator. Unknown AST variants remain refused.

Two integration discoveries required small boundary fixes. Rust serde orders revision/definition keys differently from the existing UI's serialized identity guards. `protocol.ts` first validates the actual response, then constructs returned revision keys in canonical order and recursively restores inspection-definition key order from the captured request. It preserves actual returned coordinates/values, schema-supported extra fields and missingness. Tests prove changed native values cannot be masked and mismatched coordinates still refuse. Native ordinary sorts now require declared source columns even when row objects retain undeclared keys, with the exact existing `MISSING_FIELD` diagnostic. Generated Pivot sort semantics are unchanged.
